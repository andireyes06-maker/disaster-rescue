# Whole-product audit, 28 October 2026

Scope: API routes, website pages, mobile screens. Read-only; no code changed by the audit. Three subagents read the code (Sonnet). Results are static reading only. Nothing was run in a browser or on a device. Each item is marked:
- **Checked**: I re-read the cited line myself.
- **Reported**: from the subagent only, not yet re-checked.

Verdict in short: role gating holds for API, website, and mobile. No staff screen is reachable by residents, and retired roles are blocked. The defects are reliability and error-handling problems, not access problems.

## Priority list

### High
1. **Mobile: joined team stream may crash on tab return** (reported). `mobile/lib/data/services.dart:327`, `:354`; `mobile/lib/features/responder/assigned_list_page.dart:96`, `:180`. The joined stream is single-subscription, and the tab view disposes the tab. Switching away and back can throw `Stream has already been listened to`. This is the same error as the earlier responder crash.
2. **Mobile: large phone photos block submission** (checked for the limit, reported for the missing resize). `mobile/lib/data/report_models.dart:30`, `:213-215`. Photos over 5 MB are refused, and a photo is required, so a resident with a large camera photo cannot submit. The photos are not downscaled first.
3. **Mobile: "Pick on a map" needs GPS** (reported). `mobile/lib/features/report/location_picker.dart:106-111`, copy at `:22-26`. A resident with location turned off is told to pick on the map, but the map option still needs a GPS fix, so they cannot report.
4. **API: unvalidated IDs return 500** (reported). `api/src/routes/users.js:22`, `teams.js:63`, `notifications.js:16`, `auth.js:91` and `:110`. Only `reports.js:14` checks the ID. An ID with a slash, for example, reaches Firestore and fails as 500 instead of 404.
5. **API: closing a help request** (partly checked). `api/src/routes/auth.js:110-117` writes the close and the audit in two steps. Closing a missing request fails with 500 (reported). Closing an already-closed one rewrites `closedAt` and writes a second audit row (reported).

### Medium
6. **Mobile: sign-out may keep push bindings** (reported). `push_registration.dart:99`, `notifications.js:35`. If the sign-out call fails, the next account gets 409, and the old account's pushes keep arriving.
7. **Mobile: idle sign-out ignores pushed pages** (reported). `idle_sign_out.dart:49`. A resident on a pushed page can be signed out after 30 minutes and lose photos.
8. **Mobile: profile errors hidden** (reported). `services.dart:640`. Offline, the profile shows "Not set", and the retry never appears.
9. **Mobile: draft restore loses contact details** (reported). `report_flow_page.dart:184`, `:542`. "Continue draft" clears the prefilled name and phone, and does not restore the locality.
10. **Mobile: Submit silently does nothing** (reported). `report_flow_page.dart:279`, after an uncertain send.
11. **API: verify is not resumable** (reported). `api/src/services/reviewService.js:107-112`. A retry after a partial failure gets 409, and the audit and reporter notice are lost.
12. **API: 10,000-row cap on unfiltered reads** (reported). `firestoreRepo.js:75`, `publicIncidentService.js:23`. Past the cap the public map returns 413.
13. **Website: Move-team dialog has no focus trap or Escape** (reported). `web/src/features/users/UsersPage.tsx:152`. The dialog has `role="dialog"` and `aria-modal`, but I did not confirm focus handling.
14. **Website: failed poll empties the password-help list** (reported). `web/src/features/admin/PasswordHelpPanel.tsx:22`, `:30`. A network blip shows "No open requests".
15. **Website: "Other" team without a label** (reported). `TeamsPage.tsx:97`, `:125`. The form does not validate it client-side, so the user gets the generic error.
16. **Website: Cancelled view ignores loading and error** (reported). `ReportQueue.tsx:110`, `:165`, `:190`. While loading or failing it says "No reports match" and the count shows 0.

### Low
- Mobile: 20-second upload timeout makes slow uploads look uncertain (`api_client.dart:22`).
- Mobile: responder Notifications tab label lacks "new" (`role_gate.dart:179`).
- Mobile: `nav.pop` without a mounted check (`my_reports_page.dart:278`).
- Mobile: `validatePhoto` reply omits the file name (`report_models.dart:239`).
- API: `teams.js:50-58` POST ignores `kindLabel`; PATCH enforces it.
- API: no test for `GET /api/stats/team`.
- Website: geolocation denial message can imply a save (`OperationForm.tsx:134`).

## Design choices, not defects (for your decision)
- Password reset sets the password to the account email. This is the owner's accepted risk (`api/src/routes/auth.js:86`). Worth a security review, not a change in this pass.
- Change-password reauth bypasses the sign-in lockout. Firebase's own rate limit still applies.
- HTTP 429 is treated as an uncertain send.
- Opening the bell marks notifications read. The audit says this, but my spot check found the page marks only the item tapped (`notifications_page.dart:30`). Treat the website and mobile claims as unverified.
- Drafts are saved only after an uncertain send.
- Admins change roles with no confirmation.

## Not verified
Flutter analyze and tests, Firestore rules and indexes, device behavior, browser focus behavior, and the trust-proxy setting in deployment.

## Suggested order of fixes
1. Items 1, 2, 4 (crash, photo blocking, ID handling). These affect real users now.
2. Item 3 (location fallback), then 6 to 10 for mobile reliability.
3. Items 11 to 16 for responder and admin reliability.
4. Low items as cleanup.
